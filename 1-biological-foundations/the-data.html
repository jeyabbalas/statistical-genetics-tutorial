What genotype–phenotype data looks like

The earlier pages explained where each number comes from. This page shows the numbers as you receive them from UK Biobank: a participant table whose columns are named by field, instance and array index; long tables of hospital, primary-care and death records; genotype files in PLINK, BGEN and VCF format; the matrices that go into a GWAS; and the summary statistics that come out. It ends with how access to the data works today.

Core for Lecture 2 ≈ 45 min Shows up in the data as: eid · p21001_i0 · hesin_diag · .bed/.bim/.fam · .bgen · .vcf · .regenie
Mental model

Three tables and one big matrix, joined by IDs

UK Biobank data are a participant table (one row per eid), long event tables (many rows per eid), a genotype matrix (participants × variants) and a variant table (one row per variant). You join them on eid and on variant ID, and a GWAS turns each column of the genotype matrix into one row of summary statistics.

  • The participant table has one row per participant (501,938 in the Showcase counts)1 and one column per field, instance and array index, for example p21001_i0; many values are codes that need decoding.
  • Event tables of hospital, primary-care and death records have one row per record; you aggregate them per eid into binary or time-to-event phenotypes.
  • Genotype files store the matrix together with its list of people and its variant table: PLINK .bed/.bim/.fam for array calls, BGEN for imputed probabilities, VCF for sequencing.
  • A GWAS regresses the phenotype on the covariates plus one genotype column at a time, reading the genotype file in blocks because the whole matrix does not fit in memory.
  • The output is a table of summary statistics, one row per variant, drawn as Manhattan and QQ plots. Results like these are what may leave the analysis platform.

The participant table: fields, instances and arrays Core

UK Biobank publishes a catalog of every variable it holds, the Data Showcase. It is public and lists each variable's description, units, number of participants and data-coding, but it contains no individual-level data.2 Each variable is a data-field with a numeric Field ID. Field 31 is sex, Field 21001 is body mass index (BMI) and Field 30780 is LDL cholesterol measured directly in blood.1

Two more indices say which value of a field you are looking at:3

  • The instance says when the value was collected. For assessment-centre data, instance 0 is the baseline visit (2006–2010), 1 the first repeat visit (2012–13), 2 the first imaging visit (2014 onwards) and 3 the first repeat imaging visit (2019 onwards).4 For online questionnaires and accelerometry, instances number repeats of that measurement, not visits.5
  • The array index separates several values recorded at the same instance: two automated systolic blood-pressure readings (Field 4080, indices 0 and 1), up to 37 self-reported illnesses (Field 20002), up to 259 hospital diagnosis codes (Field 41270), and 40 genetic principal components (Field 22009, indices 1 to 40).1

On the Research Analysis Platform (RAP), the cloud system where approved researchers analyze UK Biobank data (see getting access), participant-level fields sit in a database whose columns are named p<field>_i<instance>_a<array>. The _i part is left out for fields that are not instanced, and the _a part for fields that are not arrayed.6 Files downloaded in earlier years named the same column field-instance.array, for example 4080-0.1.3

Common confusion Multi-select fields: the documentation shows two naming forms

A multi-select field holds several answers at once, such as Field 41270 (all ICD-10 diagnosis codes from hospital records) or Field 20002 (self-reported illnesses). The RAP documentation says such fields arrive as one column that holds a list, without _a: p41270.6 A UK Biobank help article instead shows Field 20002 as numbered columns, such as p20002_i2_a1.5 The two sources disagree, so before you write code, check which form your own dataset uses in its data dictionary.

Many fields store codes rather than measurements. A data-coding is the lookup table that turns each code into its meaning. Sex (Field 31) uses coding 9, where 0 = Female and 1 = Male. Smoking status (Field 20116) uses coding 90: −3 = Prefer not to answer, 0 = Never, 1 = Previous, 2 = Current. Assessment centre (Field 54) uses coding 10, where 11010 = Leeds.1 Many touchscreen questions also use −1 for "Do not know" and −3 for "Prefer not to answer".7 If you leave these codes in place, a regression treats them as numbers.

Each row is one participant, identified by the eid (encoded participant ID). On the RAP an eid is a 7-digit number, typically between 1,000,000 and 6,000,000, and every access application receives its own random set of eids, so the same person has different eids in different projects.8 Within one project the same eid appears in the participant table, in the .fam files of the array genotypes and in the headers of the sequencing files, so these can be joined without translating IDs.8 Data from two different projects cannot be joined on eid.

Participants can withdraw. When someone asks that their data no longer be used, UK Biobank tells researchers, who must remove that participant from further analyses.9 On the RAP, project administrators are notified and have 90 days to update their project, after which the participant's data are removed automatically.10 In the headers of sequencing files, withdrawn participants appear as W000001, W000002 and so on.8

Long tables: hospital, primary-care and death records Core

Health records do not fit in one row per person, because one participant has no hospital stays and another has dozens. UK Biobank therefore provides record-level tables in long format: one row per record, with the eid in every row.14 The records come from national hospital, primary-care (GP) and death registries; the UK Biobank page explains how they are linked to participants. On the RAP these tables keep the column names used in UK Biobank's documentation.6

Participant 2905163 has two episodes in these rows; the 2014 episode (ins_index 4) has a primary diagnosis in block I20–I25, which ICD-10 titles "Ischaemic heart diseases".17 To turn rows like these into a phenotype, you aggregate them per eid. This query (SQL, which runs on the RAP's database) finds each participant's first hospital episode with a code in I20–I25:

first_cad.sql
SELECT d.eid, MIN(h.epistart) AS first_cad_date
FROM hesin_diag AS d
JOIN hesin AS h
  ON h.eid = d.eid AND h.ins_index = d.ins_index
WHERE substr(d.diag_icd10, 1, 3) BETWEEN 'I20' AND 'I25'
GROUP BY d.eid;

The figure shows the two common outcome types:

  • Binary (case or control): a participant is a case if any record carries a qualifying code, otherwise a control. You choose which sources count (hospital, death, primary care, self-report), which diagnosis positions count, and what to do with people who were already ill at baseline. The phenotypes page discusses these case definitions.
  • Time-to-event: the time from the baseline visit (p53_i0, date of attending the assessment centre) to the first qualifying event. People without an event are censored at death or at the end of follow-up. UK Biobank estimates that its records are mostly complete up to these dates: hospital data for England 31 March 2023, Scotland 31 August 2022 and Wales 31 May 2022; deaths in England and Wales 31 August 2024 and in Scotland 30 November 2024. These dates are guidance only; UK Biobank does not cut the data at them.18
Common confusion Four traps in the record tables
  • ins_index does not number episodes in date order.19 Sort by epistart or admidate.
  • Primary-care data cover about 45% of participants (about 230,000), use Read codes rather than ICD-10, and contain placeholder dates: 01/01/1901 means the event was dated before the participant's birth, 02/02/1902 on the date of birth, 03/03/1903 later in the year of birth, and 07/07/2037 in the future.15 Remove or recode these before computing times.
  • A person with no hospital record is not proven to be free of disease: hospital records only capture inpatient stays, and coverage differs between countries and years.14, 18
  • Codes have no dot, and a prefix match such as LIKE 'I21%' catches every subcode of I21.14
In the data Ready-made outcome fields

UK Biobank also derives participant-level summaries from these tables. Field 41270 lists every ICD-10 code in a participant's hospital records, with dates in Field 41280. The "first occurrence" fields (category 1712) give the first date of each 3-character ICD-10 code across primary care, hospital, death and self-report data. The algorithmically defined outcomes (category 42) cover conditions such as myocardial infarction and stroke.14, 20, 21 They save work, but read how each was built before you rely on it.

Genotype files: PLINK, BGEN and VCF Core

Genotypes are stored apart from the participant table because they are large. Three formats cover most of what you will meet. Each one stores a genotype matrix (people in rows, variants in columns), a list of the people and a table of the variants. They differ in what one entry holds: a called genotype (0, 1, 2 or missing), three genotype probabilities, or several text fields per person.

PLINK binary filesets: .bed, .bim and .fam

PLINK is a command-line program for genotype quality control and association testing; versions 1.9 and 2.0 are in use.22 Its binary fileset stores one genotype matrix in three files that share a name:23

  • .fam: one line per person (a row of the matrix), six columns and no header: family ID, individual ID, father, mother, sex (1 = male, 2 = female, 0 = unknown) and phenotype (1 = control, 2 = case, −9 or 0 = missing; other numbers are read as a quantitative trait). In UK Biobank files the IDs are the project's eids.8
  • .bim: one line per variant (a column of the matrix), six columns and no header: chromosome, variant ID, position in centimorgans (often 0), base-pair position, allele 1 (A1) and allele 2 (A2). PLINK counts copies of A1, which is usually the minor allele.
  • .bed: the entries, packed 2 bits per genotype. After a 3-byte header (6c 1b 01), each variant gets ⌈n/4⌉ bytes in .bim order, and within each byte the first person sits in the lowest two bits. 00 = two copies of A1, 01 = missing, 10 = one copy, 11 = no copies.

Why bits? A text table with one character per genotype and a separator needs at least 2 bytes per entry; a .bed file needs a quarter of a byte. The Session 1 practical's PennCATH data (1,401 people, 861,473 markers)25 fit in 3 + 861,473 × 351 = 302,377,026 bytes, about 302 MB (our arithmetic). UK Biobank's array genotypes (Field 22418) are PLINK filesets on GRCh37, one per chromosome.13 On the RAP, files that cover the whole cohort are named ukb<field>_c<chromosome>_b<block>_v<version>, so the chromosome 12 array calls start with ukb22418_c12_.8

PLINK 2 has its own binary fileset, .pgen, .pvar and .psam (often called PGEN). The three files play the same roles as .bed, .bim and .fam, and the format can also store dosages, phased genotypes and variants with more than two alleles. PLINK 2 reads .bed filesets too.68

BGEN: genotype probabilities for imputed data

Imputation predicts variants that the array did not measure, by matching each person's measured alleles to haplotypes in a reference panel (see phasing and genotype imputation). The prediction is uncertain, so for each person and variant it gives three probabilities, P(AA), P(AB) and P(BB), for a variant with alleles A and B. The expected number of B alleles, P(AB) + 2 × P(BB), is the dosage, a number from 0 to 2. BGEN is a binary format designed to store such probabilities compactly.27, 28

A version 1.2 file has a header (number of variants, number of samples, and flags for compression and layout), optional sample identifiers, and then one block per variant. Each block starts with the variant's identifying data (ID, rsID, chromosome, position, alleles) followed by its compressed probabilities. For two alleles and unphased data, the file stores P(AA) and P(AB) for each person as B-bit integers, each divided by 2B − 1; P(BB) is 1 minus the other two.27

UK Biobank's imputed genotypes (Field 22828) are BGEN v1.2 files with 8 bits per probability and zlib compression, one file per chromosome. In the original downloads the files are named ukb_imp_chr<N>_v3.bgen (use version 3); on the RAP they follow the naming pattern above, for example ukb22828_c1_b0_v3.bgen for chromosome 1.29, 8 Positions are on GRCh37 and 1-based, alleles are given on the forward strand, the first allele is the reference allele and the second the alternative allele, and multi-allelic sites are split into several two-allele records.29 About 96 million variants in 487,442 people take roughly 2 TB.11 Two companion files come with each .bgen:

  • .sample: the people in file order, one per line after two header lines.23, 30
  • .bgen.bgi: an index written by the program bgenix. It is an SQLite database that records each variant's chromosome, position, alleles, ID and byte offset in the .bgen file, so a program can jump to one region without reading the rest.31

Per-variant information sits in separate public tables (UK Biobank Resource 1967): for each imputed variant, its ID, rsID, position, the two alleles, minor allele frequency, minor allele and INFO score.32 These are the first four lines of the chromosome 10 file:

VCF and pVCF: sequencing data

VCF (Variant Call Format) is a tab-separated text format, usually compressed, written by sequencing pipelines.33, 34 Lines starting with ## hold meta-information, one header line starts with #CHROM, and each following line is one variant: CHROM, POS (1-based), ID, REF, ALT, QUAL, FILTER, INFO, then a FORMAT column that names the per-person fields, then one column per person.33

example.vcf Simulated
##fileformat=VCFv4.5
##FORMAT=<ID=GT,Number=1,Type=String,Description="Genotype">
#CHROM	POS	ID	REF	ALT	QUAL	FILTER	INFO	FORMAT	1384527	2905163	1052779	2271946
chr12	111803962	rs671	G	A	.	PASS	.	GT	0/0	0/1	./.	1|1

The GT (genotype) field uses allele numbers: 0 = REF, 1 = the first ALT allele. 0/0 is two reference alleles (G/G), 0/1 a heterozygote, ./. a missing call, and 1|1 two alternative alleles (A/A). A / means the genotype is unphased; a | means it is phased, so the order says which allele lies on which chromosome copy.33 Files from imputation add further per-person fields, which each file defines in its own ##FORMAT lines; common ones are DS (dosage) and GP (genotype probabilities; GP is a reserved key in the specification).33 The same people and rs671 genotypes appear in the PLINK example above, but here the position is 111,803,962: sequencing data use GRCh38.

A pVCF (project-level VCF) holds all participants of a study in one file per genomic region, genotyped jointly so that every site has an entry for every person (a genotype call or a missing value). UK Biobank's exome sequencing (Field 23157) and genome sequencing (Field 24310) data are provided as pVCF files on GRCh38, with PLINK and BGEN versions alongside.13

Common confusion The same variant has different coordinates in different files

The array files and the original imputed files (Field 22828) use GRCh37; sequencing and the TOPMed imputation use GRCh38. rs671 is at chr12:112,241,766 on GRCh37 and chr12:111,803,962 on GRCh38.24 Check the build before you merge files or look up a position (see reference genomes and builds), and convert coordinates with liftover when you must combine builds.

The analysis-ready matrix Core

A GWAS needs three aligned objects that contain the same people in the same order:

  • y, the phenotype: a vector of length n, for example LDL cholesterol, or coronary artery disease coded 0/1.
  • C, the covariates: an n × k matrix. A covariate is a variable that is adjusted for in every test, such as age, sex, genotyping array or batch, and the first 10 or more genetic principal components. Covariates remove variation that is not of interest and protect against confounding, for example by ancestry (see population stratification).37, 11
  • G, the genotype matrix: n × m, with entries 0, 1 or 2 copies of the counted allele, or a dosage between 0 and 2.

Two kinds of filter shape these matrices:

  • Sample filters remove rows: withdrawn participants; samples that failed quality control (see sample QC), such as outliers in missingness or heterozygosity (Field 22027 flags 968) or a mismatch between recorded and genetic sex;13 people outside the analysis subset, such as a group defined by genetic similarity (see ancestry in UK Biobank); and relatives. About 30% of UK Biobank participants have a relative of third degree or closer in the cohort,11 so analyses either remove one of each related pair or use a model that allows for relatedness (below).
  • Variant filters remove columns: minor allele frequency or minor allele count (REGENIE skips variants with a minor allele count below 5 by default), imputation INFO score, the Hardy–Weinberg test, and missingness.38 Thresholds differ between studies; the Session 1 practical, for example, drops variants and people with more than 1% missing calls.25

Then size decides how the software works. With n ≈ 487,000 people and about 96 million imputed variants, G has about 4.7 × 1013 entries. Stored as 8-byte numbers that would be about 380 TB (our arithmetic), against roughly 2 TB for the compressed BGEN files.11 No program loads G at once. Association software reads the genotype file one block of variants at a time, tests each variant, writes its row of results and moves on. The work per variant is small: residualize y on C once, residualize each column gj on C, and the slope of the one-variable regression of one residual on the other is the same estimate β̂j as in the full model y = Cα + gjβj + ε.39

REGENIE is the GWAS program used in Session 2.40, 39 It works in two steps:39, 41

  1. Step 1 fits a whole-genome ridge regression of y on blocks of genotyped variants (typically an LD-pruned set of common array variants)37 and chooses the amount of shrinkage by cross-validation. The fit predicts each person's phenotype from their genome-wide genotypes, which captures the polygenic part of y together with population structure and relatedness. Step 1 makes one prediction per chromosome that leaves that chromosome out: the leave-one-chromosome-out (LOCO) predictions.
  2. Step 2 tests each variant on chromosome c. For a quantitative trait it subtracts the LOCO prediction for c from y; for a binary trait it uses the prediction as an offset in a logistic model. Optional Firth or saddle-point corrections, applied to variants whose first p-value is small (below 0.05 by default), keep p-values accurate for rare variants and unbalanced case–control ratios.38

Leaving the tested chromosome out matters. If the prediction used variants near the tested variant, it would already contain part of that variant's own association, and subtracting it would remove real signal.39

A linear mixed model (LMM) reaches the same goal in another way. It adds a random effect u with covariance proportional to the genetic relationship matrix (an n × n matrix of genome-wide genetic similarity between people), y = Cα + gjβj + u + ε, so related people and structured samples can stay in the analysis. BOLT-LMM, SAIGE and fastGWA are mixed-model programs; REGENIE's step 1 approximates the same polygenic term with ridge regression.39

REGENIE reads the phenotypes and covariates from text files with a header that starts FID IID, missing values as NA, and binary traits coded 0 = control, 1 = case.38 That differs from the .fam convention of 1 = control, 2 = case, −9 = missing, so phenotypes copied from a .fam file must be recoded.37

Common confusion Joining the pieces
  • Join on eid, never on row order: the .fam, the BGEN .sample file and your phenotype table list people in different orders.
  • Use eids from one project only, and drop withdrawn eids everywhere.
  • Recode special values (−1, −3) and translate sex codes (0/1 in Field 31, 1/2 in .fam).
  • REGENIE removes people who have a missing value in any covariate in the analysis,38 so check how many remain.

Summary statistics are the per-variant results of a GWAS: one row per variant with its alleles, allele frequency, effect estimate, standard error and p-value. They contain no individual-level data, which is why they can be published and combined across studies.

Common confusion Which allele does BETA refer to?

By default REGENIE treats the last allele in a .bim or BGEN file as the reference (ALLELE0), so ALLELE1 is the first allele; the option --ref-first reverses this.38 In a .bim file the first allele is A1, usually the minor allele, while in UK Biobank's BGEN files the first allele is the reference allele.23, 29 Always read BETA together with ALLELE1, and match alleles before you compare two studies (see strands in SNP data).

Manhattan plots and genome-wide significance

A Manhattan plot draws every row as a point: x is the genomic position, with the chromosomes laid end to end in alternating colors, and y is −log10 p. Associated regions appear as narrow columns of points, because variants in linkage disequilibrium with a causal variant share its association (see association signals are peaks).

Why not call everything with p < 0.05 significant? This is the problem of multiple testing: if you run many tests at level α, about a fraction α of the tests with no true effect (the true-null tests) pass by chance. Testing 5 million null variants at 0.05 would give about 250,000 false positives. The usual genome-wide significance threshold, p < 5 × 10−8, is a Bonferroni-type correction: 0.05 divided by about one million, the estimated number of independent common-variant tests across the genome in samples genetically similar to European reference populations.42, 43 An earlier calculation for a gene-based study had arrived at the same number.44, 43 The threshold reflects the number of independent tests in the genome (see the effective number of tests), not the number of rows in your file. Pe'er and colleagues estimated about twice as many independent tests in samples genetically similar to African reference populations, which would call for a threshold about half as large.42

QQ plots and the genomic inflation factor

A QQ plot (quantile–quantile plot) sorts the m observed p-values and plots −log10 of each against the value expected if no variant were associated: −log10((i − 0.5)/m) for the i-th smallest. If the tests behave as expected under the null, the points follow the diagonal.

The genomic inflation factor λ (lambda) summarizes the bulk of the tests: λ = (median of the observed χ² statistics) ÷ 0.455, the median of a χ² distribution with 1 degree of freedom.49 λ ≈ 1 means the bulk of the tests behaves as expected. λ > 1 can come from confounding, such as population stratification, cryptic relatedness or batch effects, but also from true polygenic signal: when a trait is influenced by thousands of variants, λ grows with sample size even without any confounding.50 LD score regression separates the two sources (see LD scores).51

Meta-analysis and public summary statistics

A meta-analysis combines the summary statistics for the same variant from several studies. The fixed-effect inverse-variance method weights each study's estimate by the inverse of its squared standard error:52

β̂ = Σk wk β̂k / Σk wk, wk = 1 / SEk², SE(β̂) = 1 / √(Σk wk)

Random-effects models let the true effect differ between studies, and heterogeneity tests ask whether it does.53 Before combining, the effect allele must be the same in every study. In Session 2 you will combine breast-cancer summary statistics at the TERT region from three strata that the course files label AFR, ASN and EUR (the course calls them ancestry strata) with the program METASOFT. You will compare fixed-effect, conventional random-effects and RE2 models; RE2 is Han and Eskin's random-effects method, which, unlike the conventional random-effects model, can have more power than the fixed-effect model when the effect differs between studies.40, 54

Many studies publish their summary statistics. The NHGRI-EBI GWAS Catalog holds 203,002 full summary-statistics datasets (as of 3 October 2026).55 For UK Biobank, Pan-UKBB provides GWAS results for thousands of phenotypes across six genetic ancestry groups, and the Neale lab released an earlier set of UK Biobank GWAS results.56, 57 Downloading public summary statistics needs no application.

Getting access and working responsibly Core

UK Biobank data are available to registered researchers at academic, charity, government and commercial organizations, for health-related research in the public interest.58 The usual route has four steps:

  1. Register as a researcher on UK Biobank's Access Management System.
  2. Apply with a description of the research question and a list of the data-fields you need.
  3. Approval: your institution signs a Material Transfer Agreement (its contract with UK Biobank that sets the conditions for using the data)65 and you pay an access fee. At the time of writing (UK Biobank's Fees page, checked 21 October 2026), three years of access cost £3,000 for Tier 1 (questionnaires, physical measures, linked health records), £6,000 for Tier 2 (adding assays, proteomics, and measured and imputed genotypes) or £9,000 for Tier 3 (adding imaging, exomes and genomes), excluding VAT, and £500 for students and for researchers in lower-income countries. For a limited period, the biochemical, hematological and proteomic assay data are offered under Tier 1 and imaging data under Tier 2 fees.58, 59
  4. Data are dispensed into a project on the RAP, with eids specific to your application.8

Obligations continue during the project: annual reports, telling UK Biobank about publications, and returning results to UK Biobank.58

The RAP is a cloud platform built by DNAnexus and hosted on Amazon Web Services; it launched publicly on 28 September 2021.60 Tabular fields sit in a Spark SQL database, and bulk data such as genotype and sequencing files sit as files in the project.8 You pay for compute and storage as you use them; every researcher receives £40 of credit, which UK Biobank says supports about 100 hours of analysis.61 The tools include PLINK, PLINK 2, REGENIE, BOLT-LMM, bgenix and bcftools (in the "Swiss Army Knife" app), JupyterLab with Hail for analyses on Spark, RStudio, and Table Exporter for writing selected fields to a file.62 Since mid-2024, data for new projects have been made available on the platform only, with limited exceptions ("platform by default"), and exome and genome sequencing data cannot be downloaded at all, even with an exemption.63, 64, 65

Rules that apply whatever the status

  • Use the data only for the approved project described in your application.58, 65
  • Never try to identify a participant. If it happens by accident, report it to UK Biobank immediately, do not disclose it and do not contact the person.67
  • Remove withdrawn participants from your analyses when UK Biobank tells you to.9, 10
  • Keep participant-level data on the platform and take out only results, through the output checks.64, 66
  • Never put participant-level data, not even a few example rows, in a code repository or next to published code. UK Biobank runs automated daily scans for such data, and it has said that researchers whose participant data are found in a code repository will have their access stopped.66 Use simulated data, as this page does, for examples.
Key points
  • The participant table has one row per eid; its columns are named by field, instance and array index (p21001_i0, legacy 21001-0.0), and coded values (−3, negative batch numbers, 0/1 sex) must be decoded with the Showcase data-codings.
  • eids are specific to each project. They join the participant table, record tables and genotype files of one project, and withdrawn participants must be removed.
  • Hospital, primary-care and death records are long tables (one row per record); you aggregate them per eid into binary or time-to-event phenotypes, with attention to dates, coverage and censoring.
  • PLINK filesets (.bed 2-bit entries, .bim variants, .fam people) hold array calls; BGEN holds imputed probabilities and dosages; VCF/pVCF holds sequencing calls. Arrays and the original imputation (Field 22828) use GRCh37; sequencing uses GRCh38.
  • A GWAS fits y = Cα + gjβj + ε for each filtered column of G, reading the genotypes in blocks; REGENIE's step 1 builds LOCO predictions and step 2 tests each variant.
  • Summary statistics have one row per variant (BETA per copy of ALLELE1, SE, LOG10P). Manhattan plots show them along the genome against the 5 × 10−8 line; QQ plots and λ check the bulk; meta-analysis combines studies; only results like these leave the platform.

Check your understanding

What is in the column p30780_i1?

Field 30780, LDL cholesterol measured directly, at instance 1: the first repeat assessment visit (2012–13). There is no _a part because the field holds one value per visit.

A colleague sends you a phenotype file from their own UK Biobank project. Can you join it to your genotypes on eid?

No. Each access application receives its own random set of eids, so the same person has different eids in the two projects. Only data within one project can be joined on eid.

A .bed byte for four people reads 0xE4 (binary 11100100). What are their genotypes?

Read the bit pairs from right to left: 00, 01, 10, 11. Person 1 has two copies of A1, person 2 is missing, person 3 has one copy (heterozygous) and person 4 has no copies of A1 (two copies of A2).

For one person, a BGEN file gives P(AA) = 0.1, P(AB) = 0.6 and P(BB) = 0.3. What is the dosage of allele B?

0.6 + 2 × 0.3 = 1.2. The dosage is the expected number of B alleles.

A REGENIE row has LOG10P = 9.2. What is p, and is the variant genome-wide significant?

p = 10−9.2 ≈ 6.3 × 10−10. That is below 5 × 10−8 (LOG10P above 7.3), so yes.

Your GWAS of 20,000 people has λ = 1.25. What could cause this, and what would you check?

Confounding (population stratification, relatedness, batch effects) or true polygenic signal. Check that the principal components and array or batch are in the covariates and that relatives are handled, look at the QQ plot, and use LD score regression: an intercept near 1 points to polygenicity, an intercept well above 1 to confounding.

Why does REGENIE read the imputed genotypes in blocks instead of loading the matrix?

The matrix has about 4.7 × 1013 entries (487,000 people × 96 million variants), about 380 TB as 8-byte numbers. Each variant's test only needs that one column plus quantities computed once (y and the covariates), so the program reads a block of columns, tests them, writes their rows and moves on.
