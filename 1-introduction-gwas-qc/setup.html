Run the practical on your own computer or in the cloud

The practical was written for Biowulf, the shared Linux computing cluster of the US National Institutes of Health, where PLINK is already installed and the data sit in a shared folder. Readers of this site have no account there. This page builds the same working environment on your own computer, or on a computer rented from a cloud service: one project folder, three folder variables, three programs (PLINK 1.9, R with three packages, and GrafAnc) and six data files, each compared with its published checksum, a number computed from every byte of a file that shows whether the file arrived complete and unchanged. After that, every command of the practical runs as written.

One folder, three variables, three programs, six checked files

The practical needs one project folder whose three data subfolders are named by the variables input_dir, reference_dir and analysis_dir, three programs that the shell can find, and six input files whose sizes and checksums match the published ones. Once those exist, the practical's commands run unchanged; only the values of the three variables differ from Biowulf.

  • What the computer needs. About 5 GB of free disk, 4–8 GB of memory, and macOS, Linux or Windows with WSL.
  • One folder, three variables. The same layout as the in-browser lab, under ~/statgen-workshop; the variables are set once and kept for every new terminal and for R.
  • Three programs. PLINK 1.9 from its official zip file or a package manager, R with tidyverse, data.table and glue, and GrafAnc, which runs only on Linux: natively, in WSL, or in Docker.
  • Six files, checked. Download PennCATH and the reference panel from the workshop's shared folder and compare each file's size and SHA-256 checksum with the table.
  • Run it. Either the practical's own R Markdown file with its setup chunk replaced, or this site's scripts, which run all eight steps and draw the plots.
  • When something fails. Almost every failure is one of six causes: PATH, permissions, processor type, an incomplete file, a path with a space, or a missing library.

What your computer needs Core

The input files take 338 MB. The other numbers in the table were measured when the whole practical was run for this site with real PLINK 1.9.0 and GrafAnc on a Mac (an Apple M5 Pro with 18 cores and 48 GB of memory, November 2026); a computer with fewer cores takes longer. PLINK writes binary genotype files whose size follows from the numbers of people and SNPs (\(3 + m\lceil n/4 \rceil\) bytes for \(m\) SNPs and \(n\) people)1, and text reports with one line per SNP, per person or per pair of people, so the sizes can be worked out before anything runs.

One folder, three variables Core

A terminal is the window where you type commands; the program inside it that reads them is the shell (bash on Linux and WSL, zsh on macOS; both treat every command here the same way). Every command in the practical names its files through three folder variables: ${input_dir} for PennCATH, ${reference_dir} for the 1000 Genomes reference panel and ${analysis_dir} for everything the steps write.5 On Biowulf they point to /data/… folders. On your computer they point into one project folder, with the same layout as the in-browser lab:

~/statgen-workshop/                       the project folder (~ is your home folder)
├── data/inputs/penncath_withPheno/     = input_dir
│   ├── penncath.bed                    302,377,026 bytes
│   ├── penncath.bim                    24,051,506 bytes
│   └── penncath.fam                    25,686 bytes
├── data/inputs/ref/                    = reference_dir
│   ├── all_pops_1kgenomes_markersForPCA.bed
│   ├── all_pops_1kgenomes_markersForPCA.bim
│   └── all_pops_1kgenomes_markersForPCA.fam
├── analysis/                           = analysis_dir: every output, about 3 GB
├── tools/                              plink (this folder goes on PATH)
└── scripts/                            this site's scripts, if you use them

Keep the folder name free of spaces and special characters: the practical writes ${input_dir} without quotation marks, so the shell would split a path such as ~/My Projects into two words. Keep it out of folders that a cloud service synchronizes (iCloud Drive, OneDrive, Dropbox, Google Drive), which would upload about 3 GB of intermediate files. On Windows, keep it in the Linux home folder of WSL, not under /mnt/c, where Linux programs read and write files much more slowly.6

Create the folders and set the variables in a terminal. export makes a variable an environment variable, one that the shell passes on to every program it starts; PATH is the environment variable that lists the folders in which the shell looks for programs, so putting tools first lets you type plink after copying PLINK there:

bash or zsh 
# Create the folders (once)
mkdir -p ~/statgen-workshop/data/inputs/penncath_withPheno \
         ~/statgen-workshop/data/inputs/ref \
         ~/statgen-workshop/analysis \
         ~/statgen-workshop/tools \
         ~/statgen-workshop/scripts

# Set the three folder variables and PATH for this terminal
export input_dir="$HOME/statgen-workshop/data/inputs/penncath_withPheno"
export reference_dir="$HOME/statgen-workshop/data/inputs/ref"
export analysis_dir="$HOME/statgen-workshop/analysis"
export PATH="$HOME/statgen-workshop/tools:$PATH"

These settings last until the terminal closes. To have them in every new terminal, add the four export lines once to the shell's start-up file, which the shell reads when it starts: ~/.zshrc on macOS, ~/.bashrc on Linux and WSL. The quoted 'EOF' keeps $HOME and $PATH as written, so they are expanded each time a terminal starts:

bash or zsh · once 
# On Linux and WSL: ~/.bashrc
cat >> ~/.zshrc <<'EOF'
export input_dir="$HOME/statgen-workshop/data/inputs/penncath_withPheno"
export reference_dir="$HOME/statgen-workshop/data/inputs/ref"
export analysis_dir="$HOME/statgen-workshop/analysis"
export PATH="$HOME/statgen-workshop/tools:$PATH"
EOF

R does not read those files when RStudio is opened from the Dock, the Start menu or a launcher, and the practical's bash chunks inherit their environment from R. The practical therefore sets the folders in R and passes them on with Sys.setenv(); on your computer the R version adds the tools folder to R's PATH as well:

r · replaces the practical's setup chunk 
# The folders, in R
base          <- path.expand("~/statgen-workshop")
input_dir     <- file.path(base, "data", "inputs", "penncath_withPheno")
reference_dir <- file.path(base, "data", "inputs", "ref")
analysis_dir  <- file.path(base, "analysis")
dir.create(analysis_dir, recursive = TRUE, showWarnings = FALSE)
Sys.setenv(input_dir = input_dir, reference_dir = reference_dir, analysis_dir = analysis_dir,
           PATH = paste(file.path(base, "tools"), Sys.getenv("PATH"), sep = .Platform$path.sep))

path.expand() replaces ~ with your home folder; file.path() joins folder names with /; .Platform$path.sep is the character that separates folders in PATH (: on macOS and Linux).

Install the programs Core

Pick your system in any of the tab sets below; all of them switch together. Each subsection ends with a command that shows the program works. On Windows, everything happens inside WSL, so the Windows tab starts by installing it.

PLINK 1.9

The practical uses PLINK 1.9, whose official stable version 1.9.0 was released on 27 September 2026.7 Its download is a zip file with the program plink, a license file, two example files and prettify, a small program that lines up the columns of a text table (the practical does not use it). The macOS build runs natively on both Intel and Apple Silicon Macs. Downloading with curl in a terminal, as below, avoids a macOS block: a file downloaded by a web browser carries a quarantine mark, and Gatekeeper, the macOS check on programs from the internet, refuses to start an unsigned program that carries it.8

zsh · Terminal 
cd ~/statgen-workshop/tools
curl -fLO https://s3.amazonaws.com/plink1-assets/plink_mac_20260927.zip
unzip -o plink_mac_20260927.zip plink
rm plink_mac_20260927.zip
plink --version          # prints a line starting "PLINK v1.9"

Alternatives: brew install plink1 with Homebrew, a package manager for macOS (it installs the command plink and cannot be installed together with PuTTY, a remote-login program that also has a command called plink)9; or the conda environment below. If you downloaded the zip in a browser and macOS says the developer cannot be verified, open System Settings → Privacy & Security and click Open Anyway, or remove the quarantine mark in the terminal with xattr -d com.apple.quarantine ~/statgen-workshop/tools/plink.

bash 
sudo apt install -y curl unzip
cd ~/statgen-workshop/tools
curl -fLO https://s3.amazonaws.com/plink1-assets/plink_linux_x86_64_20260927.zip
unzip -o plink_linux_x86_64_20260927.zip plink
rm plink_linux_x86_64_20260927.zip
plink --version                       # prints a line starting "PLINK v1.9"

The apt commands on this page are for Debian and Ubuntu; other Linux systems have the same packages under similar names. This build is for x86_64 processors. On an arm64 Linux computer, or if you prefer the package manager, Ubuntu's package installs the program as plink1.9 (version 1.90b7.7 on Ubuntu 26.04 for both processor types; Ubuntu 24.04 has an older build for x86_64 only)10; link it under the name the practical uses:

sudo apt install -y plink1.9
ln -s /usr/bin/plink1.9 ~/statgen-workshop/tools/plink

First install WSL, the Windows Subsystem for Linux, which runs a Linux system (Ubuntu by default) inside Windows.11 Open PowerShell as administrator (right-click the Start button → Terminal (Admin)) and run:

PowerShell · administrator 
wsl --install

Restart Windows, open Ubuntu from the Start menu and choose a Linux user name and password. Everything from here on is typed in that Ubuntu terminal, and the project folder lives in its home folder. Then install PLINK exactly as on Linux:

bash · Ubuntu terminal 
sudo apt update && sudo apt install -y curl unzip
cd ~/statgen-workshop/tools
curl -fLO https://s3.amazonaws.com/plink1-assets/plink_linux_x86_64_20260927.zip
unzip -o plink_linux_x86_64_20260927.zip plink
rm plink_linux_x86_64_20260927.zip
plink --version                       # prints a line starting "PLINK v1.9"

PLINK also has a native Windows build (plink_win64_20260927.zip), but the practical's commands are bash commands and GrafAnc needs Linux, so WSL keeps everything in one place.

Run the mkdir and export lines of One folder, three variables first, so that ~/statgen-workshop/tools exists and is on PATH; otherwise run ./plink --version inside that folder.

R, an editor and three packages

R reads PLINK's report tables and draws the plots. The practical loads three packages: tidyverse (a collection of packages for tables and plots, including dplyr and ggplot2), data.table (for its fast file reader fread()) and glue. RStudio or Positron, both from Posit, give R an editor, a console, a plot pane and a terminal tab, and RStudio's Knit button runs an R Markdown file.12

  1. Install R from CRAN, the Comprehensive R Archive Network: take the installer for Apple Silicon (arm64) or for Intel (x86_64) to match your Mac.13 (Homebrew's R also works, but it compiles packages from source, which is much slower.)
  2. Install RStudio Desktop or Positron.
  3. In the R console, install the packages. CRAN has ready-built versions for macOS, so this takes a few minutes:
r · console 
install.packages(c("tidyverse", "data.table", "glue", "rmarkdown"))

Ubuntu's own R package is enough for the practical; CRAN's Ubuntu page shows how to get the newest R instead.13 On Linux, R packages are compiled from source, which needs a C compiler and the development files of several system libraries. These are the libraries the tidyverse needs on Ubuntu:

bash 
sudo apt install -y r-base r-base-dev build-essential \
  libcurl4-openssl-dev libssl-dev libxml2-dev libfontconfig1-dev libharfbuzz-dev \
  libfribidi-dev libfreetype6-dev libpng-dev libtiff5-dev libjpeg-dev

Then install the packages into your personal R library (compiling the tidyverse takes 10–30 minutes):

bash 
Rscript -e 'lib <- Sys.getenv("R_LIBS_USER"); dir.create(lib, recursive = TRUE, showWarnings = FALSE)
install.packages(c("tidyverse", "data.table", "glue", "rmarkdown"), lib = lib, repos = "https://cloud.r-project.org")'

For an editor, install RStudio Desktop or Positron (both have Ubuntu packages), or run R in the terminal.

Install R inside Ubuntu exactly as on Linux, so that R, PLINK and GrafAnc share one file system:

bash · Ubuntu terminal 
sudo apt install -y r-base r-base-dev build-essential \
  libcurl4-openssl-dev libssl-dev libxml2-dev libfontconfig1-dev libharfbuzz-dev \
  libfribidi-dev libfreetype6-dev libpng-dev libtiff5-dev libjpeg-dev
Rscript -e 'lib <- Sys.getenv("R_LIBS_USER"); dir.create(lib, recursive = TRUE, showWarnings = FALSE)
install.packages(c("tidyverse", "data.table", "glue", "rmarkdown"), lib = lib, repos = "https://cloud.r-project.org")'

Two ways to work with R there. In the terminal: Rscript qc_plots.R (see the scripts) writes the plots as PNG files, which you open from Windows. In an editor: Visual Studio Code with its WSL extension opens the Ubuntu folder and terminal directly. In a browser: RStudio Server in Docker (below) works with Docker Desktop's WSL integration. RStudio for Windows runs a Windows version of R, separate from the Linux system that holds PLINK and the files, so it is the least direct choice; it can read the results through the path \\wsl.localhost\Ubuntu\home\YOUR-LINUX-NAME\statgen-workshop\analysis not tested here.

Check the packages: Rscript -e 'library(tidyverse); library(data.table); library(glue)' should print the tidyverse's list of attached packages and no error.

GrafAnc

GrafAnc assigns each person to a genetic ancestry group from about 282,000 selected SNPs (The tools · GrafAnc). It is a Linux program: its repository contains a ready-built program for 64-bit Linux, bin/grafanc, which the practical runs, and its source code relies on features that only Linux has (the sysinfo system call and the /proc file system), so it cannot be compiled for macOS or Windows without changing its code.14 It also needs htslib, a C library for genomic file formats, installed on the system. On Biowulf the practical makes htslib available with module load bcftools/1.23; bcftools itself is never run. (That reading is ours: the practical does not say why it loads bcftools.)

The workshop also publishes a Docker image with GrafAnc built from a fixed version of its source, with a small patch: the original program can corrupt its output table when compiled with optimization, and it reports failure (exit status 1) even after a successful run.15 Docker runs a program inside a container, an isolated Linux environment created from an image that bundles the program with everything it needs; Docker Desktop provides it on macOS and Windows.16

None of the three routes below has been tested by us untested. (To check the lab and the PennCATH results for this site, GrafAnc was compiled on a Mac after replacing the two functions that use those Linux features; that is not one of these routes.) Steps 1–7 do not need GrafAnc, so you can set it up last.

Docker image (the only route on a Mac)

Install and start Docker Desktop, then download the image once (about 264 MB). It is built for Intel processors; on an Apple Silicon Mac Docker runs it under emulation, which --platform linux/amd64 requests explicitly:

zsh · Terminal 
docker pull --platform linux/amd64 ghcr.io/dceg-workshops/graftools:1.0.1

After the ID update of step 8, run GrafAnc on the files in the analysis folder:

docker run --rm --platform linux/amd64 --user "$(id -u):$(id -g)" \
  -v "${analysis_dir}":/work ghcr.io/dceg-workshops/graftools:1.0.1 \
  grafanc penncath.geno0.01.mind0.01.uniqueIDs penncath_grafanc_out.txt

-v "${analysis_dir}":/work makes your analysis folder appear inside the container as /work, the image's working directory (the folder in which its commands start), so GrafAnc reads and writes files there by name alone; a path such as /Users/ana/… does not exist inside the container. --user runs it under your user number, so the output file belongs to you; --rm deletes the stopped container afterwards. The image sets GRAFPATH and holds the decompressed reference table, so the practical's git clone, gunzip and module load lines are not needed.

Route 1: the repository's program, as in the practical

Install htslib's run-time library from the package manager (Ubuntu 24.04 and later call it libhts3t64; Ubuntu 22.04 calls it libhts3; Ubuntu's bcftools package installs it too). Then follow the practical: clone the repository into the analysis folder, decompress the reference table once, and point GRAFPATH at the folder that contains data/AncSnpPopAFs.txt:

bash 
sudo apt install -y libhts3t64
cd "${analysis_dir}"
git clone https://github.com/jimmy-penn/grafanc.git
gunzip grafanc/cpp/data/AncSnpPopAFs.txt.gz
export GRAFPATH="${analysis_dir}/grafanc/cpp"
"${analysis_dir}/grafanc/bin/grafanc" \
    "${analysis_dir}/penncath.geno0.01.mind0.01.uniqueIDs" \
    "${analysis_dir}/penncath_grafanc_out.txt"
head -3 "${analysis_dir}/penncath_grafanc_out.txt"

Judge success by the output file, not by the exit status: this version exits with status 1 after a successful run. If it stops with error while loading shared libraries: libhts.so.3, the library is missing.

Route 2: the Docker image

Install Docker Engine (or Docker Desktop) and use the two commands of the macOS tab; on an x86_64 computer the image runs natively.

Route 3: build it with the workshop's patch

This repeats the build steps of the workshop's Dockerfile: the same fixed version of the source, the same patch, and a similar compile command, with htslib from the package manager instead of a copy built from source. GrafAnc's own makefile expects htslib in the folder ~/htslib/1.20, so the last command compiles the files directly:15

bash 
sudo apt install -y build-essential git curl zlib1g-dev libhts-dev
cd "${analysis_dir}"
[ -d grafanc ] || git clone https://github.com/jimmy-penn/grafanc.git
cd grafanc
git checkout b5e51c78b5004a8388418ce56755bb2f71f24eb5
curl -fLO https://raw.githubusercontent.com/DCEG-workshops/statgen_workshop_tutorial/main/docker_images/GRAFTOOLS/grafanc-output.patch
git apply --unidiff-zero grafanc-output.patch
cd cpp
[ -f data/AncSnpPopAFs.txt.gz ] && gunzip data/AncSnpPopAFs.txt.gz
g++ -O2 -std=c++11 -pthread -I. -o grafanc *.cpp -lhts -lz -lm
./grafanc     # with no arguments it prints its usage

The program built here sits in cpp/, next to the data/ folder that holds the reference table, so it finds the table even without GRAFPATH; it exits with status 0 on success. Run it as in route 1, with "${analysis_dir}/grafanc/cpp/grafanc" in place of the bin/grafanc path.

WSL is Linux, so route 1 of the Linux tab works in the Ubuntu terminal unchanged: install libhts3t64, clone, decompress, set GRAFPATH and run bin/grafanc. Route 3 (build with the patch) also works there.

Alternatively install Docker Desktop for Windows and turn on its integration with your Ubuntu distribution (Settings → Resources → WSL integration); the docker commands of the macOS tab then work in the Ubuntu terminal.

Pitfall GrafAnc's exit status in scripts

A script that stops at the first failing command (bash's set -e) stops right after a successful run of the repository's bin/grafanc, because that program returns 1, the code for failure. Write grafanc … || true and then test that the output file exists and is not empty, as qc_pipeline.sh does. The patched builds (the Docker image and route 3) return 0.

Or: one conda environment for everything but GrafAnc

conda installs programs and libraries into a separate folder called an environment, without administrator rights; Miniforge is a small installer for it that uses the community channel conda-forge.17 The file environment.yml lists PLINK 1.9 (from Bioconda, the channel for bioinformatics software), R with the three packages and rmarkdown, pandoc, git, curl, unzip and htslib:

bash or zsh

Bioconda builds PLINK 1.9 for Linux and for Intel Macs only.18 On an Apple Silicon Mac, either (A) build the whole environment for Intel Macs, which then runs through Rosetta 2, Apple's translator for Intel programs, or (B) leave PLINK out and install the native macOS zip as above. Option B lasts longer: Apple says Rosetta is available through macOS 27, and from macOS 28 only for certain older games.19

zsh · Apple Silicon

CONDA_SUBDIR=osx-64 conda env create -f environment.yml

# Option B: a native environment without PLINK; PLINK from its zip file (above)
grep -v 'plink' environment.yml > environment-arm64.yml
conda env create -f environment-arm64.yml

The versions in the file were checked against the channels in November 2026, but we have not created the environment ourselves untested. GrafAnc is not in conda; use one of the routes above.

Download the data and check it Core

The size of a .bed file can also be checked against its own .bim and .fam files, because PLINK stores each SNP's genotypes in \(\lceil n/4 \rceil\) bytes after a 3-byte header (The tools · two bits per genotype). For PennCATH, \(m = 861{,}473\) SNPs (lines of the .bim) and \(n = 1{,}401\) people (lines of the .fam) give \(3 + 861{,}473 \times 351 = 302{,}377{,}026\) bytes, exactly the size in the table; a file of any other size is incomplete, and PLINK refuses it with Error: Invalid .bed file size.

bash or zsh 
$ cd "${input_dir}"
$ m=$(wc -l < penncath.bim); n=$(wc -l < penncath.fam)
$ echo "expected $(( 3 + m * ((n + 3) / 4) )), found $(( $(wc -c < penncath.bed) ))"
expected 302377026, found 302377026

Key points
  • The practical needs one project folder, three folder variables (input_dir, reference_dir, analysis_dir) set in both the shell and R, PLINK 1.9 on PATH, R with tidyverse, data.table and glue, and, for step 8, GrafAnc.
  • Plan for about 5 GB of free disk and 4–8 GB of memory; the input files take 338 MB and the outputs about 3 GB (estimates from the file formats).
  • A downloaded file is right when its size and SHA-256 checksum match the published values; a .bed file must also have exactly \(3 + m\lceil n/4 \rceil\) bytes.
  • GrafAnc is a Linux program: run it natively on Linux or in WSL (it needs the htslib library), or in the workshop's Docker image on a Mac. The unpatched program exits with status 1 even when it succeeds.
  • On your computer, only three things change in the practical: the setup chunk's paths, the module load lines, and, on macOS, how GrafAnc is started.

Check your understanding

Your download of penncath.bed has 302,377,025 bytes. The .bim file has 861,473 lines and the .fam file 1,401. Is the file complete, and what would PLINK do with it?

No. Each SNP takes \(\lceil 1{,}401/4 \rceil = 351\) bytes, so the file must have \(3 + 861{,}473 \times 351 = 302{,}377{,}026\) bytes; it is one byte short. PLINK compares the size with the one it computes from the .bim and .fam files and stops with Error: Invalid .bed file size (expected 302377026 bytes). Download the file again; its SHA-256 checksum confirms the new copy.

Yesterday's commands worked. Today, in a new terminal, the first PLINK command of step 1 stops with Error: Failed to open /penncath.bed. What happened?

The command names its input as --bfile ${input_dir}/penncath. export sets a variable only for the terminal in which it runs and the programs that terminal starts. In the new terminal input_dir is not set, the shell replaces ${input_dir} with nothing, and PLINK receives /penncath. Run the export lines again, or add them once to ~/.zshrc or ~/.bashrc so that every new terminal has them.

Why does step 8 need Docker on a Mac but not on Linux, and why does the docker run command name the files without their folder?

GrafAnc is a Linux program: the repository's ready-built program is a Linux executable, and its source code uses Linux-only system calls, so it cannot be compiled for macOS. Docker runs it in a Linux container. Inside the container your folders do not exist; -v "${analysis_dir}":/work makes the analysis folder appear as /work, the image's working directory, so names without a folder (penncath.geno0.01.mind0.01.uniqueIDs) are found there and the output is written there, which is your analysis folder.

On an Apple Silicon Mac, conda env create -f environment.yml fails because no package plink is found. Why, and what are the two ways out?

Bioconda builds PLINK 1.9 only for Linux (linux-64) and Intel Macs (osx-64), not for Apple Silicon (osx-arm64), so the solver finds no matching package. Either create the whole environment for Intel Macs with CONDA_SUBDIR=osx-64, which then runs through Rosetta 2, or leave PLINK out of the environment and install the official macOS zip, which runs natively on Apple Silicon.

The merged PennCATH + 1000 Genomes fileset has 3,884 people and at most 878,963 SNPs. How large can its .bed file be, and how much disk does step 7 need at its peak?

Each SNP takes \(\lceil 3{,}884/4 \rceil = 971\) bytes, so the file has at most \(3 + 878{,}963 \times 971 = 853{,}473{,}076\) bytes, about 0.85 GB. When --bmerge is combined with --make-bed, PLINK first writes the merged data to an intermediate fileset (…-merge.bed), then writes the final one and deletes the intermediate at the end, so for a moment both exist: about 1.7 GB on top of the files already there.

qc_pipeline.sh starts with set -e, which stops a script at the first command that fails. Two commands in the practical "fail" when everything is fine. Which, and how does the script handle them?

The first --bmerge fails by design: PLINK lists the SNPs with conflicting alleles in …-merge.missnp and exits with a non-zero status. The script appends || true and then checks whether the .missnp file exists before flipping. The repository's GrafAnc program exits with status 1 after a successful run; the script again appends || true and then requires that the output file exists and is not empty.

A classmate keeps the project in ~/Library/Mobile Documents/com~apple~CloudDocs/Stat Gen. Name two problems with this folder.

It contains a space (in Mobile Documents and Stat Gen), so the practical's unquoted ${input_dir} would be split into separate words and PLINK would not find its files. It is inside iCloud Drive, which would upload about 3 GB of intermediate files and may keep some files only online, where PLINK cannot read them. ~/statgen-workshop avoids both.
